# 架构说明

「纸上功夫」是一个单进程全栈应用:构建后 `dist/boot.js` 同时提供静态站点、tRPC API 与启动自举逻辑。本文档按「请求从哪来、数据到哪去、任务怎么跑、AI 怎么接」四条主线说明架构,帮助新开发者快速定位代码。

## 一、总览

```
浏览器(React SPA)
   │  HTTPS / HTTP
   ▼
Hono 服务器(dist/boot.js,单进程)
   ├─ 静态站点服务(src/ 构建产物)
   ├─ tRPC 路由(api/router.ts → 各业务 Router)
   │     ├─ middleware.ts:publicQuery / privateQuery / adminQuery 三级守卫
   │     └─ context.ts:session → user 身份解析
   ├─ lib/bootstrap.ts:启动自举(迁移/种子/僵尸清扫/session清理)
   ├─ lib/pipelineRunner.ts:六阶段解题流水线(异步任务)
   └─ llm/client.ts:渠道中台(多模型绑定)
   │
   ├── MySQL / TiDB(Drizzle ORM,29+ 张表)
   └── LLM 渠道(OpenAI / DeepSeek / 中转…,密钥只存服务端)
```

核心原则:**认证靠 session、判分靠官方答案、AI 走渠道中台、任务有生命周期**。

## 二、认证与权限(api/middleware.ts)

三级守卫,新增端点必须选对:

| 守卫 | 用途 | 说明 |
|------|------|------|
| `publicQuery` | 浏览类只读 | 游客可访问(真题列表/详情、SOP 条款、解析档案) |
| `privateQuery` | 写库/消耗算力 | 要求登录;`userId` 一律从 session 取,客户端传的一律忽略(防 IDOR) |
| `adminQuery` | 管理操作 | 要求管理员(渠道管理、公告发布、全站提示词) |

- `context.ts` 负责从 `Authorization: Bearer <jwt>` 解析 session → user,登录态挂在 `ctx.user`。
- 游客模式:首页等公开页可访问,涉及个人数据处显示登录引导。

## 三、数据库(Drizzle + MySQL)

- 表定义集中在 `db/schema.ts`(单一事实源),改动后 `npx drizzle-kit generate` 生成迁移,`db/migrations/` 追加式管理。
- **迁移自举**:`bootstrap` 每次启动都跑 `drizzle migrate`(幂等),新表自动进老库——「部署即自愈」,升级无需手工迁移。
- 核心表分组:
  - 账号:`users`(含 `recovery_salt` 独立盐,凭证生命周期解耦)、`sessions`
  - 内容:`passages`、`questions`(官方答案)、`methodClauses`(SOP 条款)、`knowledgeCards`
  - 学习数据:`practiceRecords`、`wrongItems`、`vocabItems`、`analyses`(解析+联想图缓存)、`answerDiffs`(差异分析缓存,UNIQUE 键)
  - AI 绑定:`channels`、`bindings`(角色→渠道绑定)、`prompts`(提示词版本化)
  - 扩展模块:`generatedSets`(AI 生题)、`retroSets`(复盘定制卷)、`interactiveRecords`(跟我练)、`tickets`/`ticketReplies`/`ticketAttachments`/`announcements`(工单公告)、`essays`/`essayDrafts`/`userMaterials`(作文工坊)、`wrongItemAnalyses`/`wrongInsights`/`wrongRecommendations`(错题诊断)
- 种子:`db/seed.ts`(SOP/真题语料/预置渠道)+ `db/final_corpus.json`(真题语料库)。
- 全量快照:`db/dump.tar.gz`(脱敏)+ `scripts_export_dump.mjs` / `scripts_restore_dump.mjs`。

## 四、六阶段解题流水线(api/lib/pipelineRunner.ts)

异步任务模型,`pipeline_jobs` 表承载状态:

```
stage1 审题(locator) → stage2 定位 → stage3 解题(solver) → stage4 校验(reviewer) → stage5 解析归档 → done
```

- **状态机**:`running / paused / done / error / cancelled`;前端可暂停/继续/停止;每阶段写库前回读控制信号。
- **任务生命周期三件套**:
  1. 启动清扫:bootstrap 把 `status=running` 全部置 `error`(进程死亡后 running 必为假)。
  2. 心跳门槛:复用/重试前检查 `updatedAt`,10 分钟静止视为僵尸,自动转 error。
  3. 总 deadline:单任务 25 分钟上限(含 5 阶段 × 3 次重试余量)。
- **断点续跑**:产物逐阶段落库(如 `payload.solveParts[qNo]` 逐题),重试从断点继续,不重跑已完成阶段。
- **判分事实源**:`officialOf(qAnswer, aiAnswer)` 单点收口——官方答案(`questions.answer`)优先,AI 答案仅降级。

## 五、LLM 渠道中台(api/llm/client.ts)

- `channels` 表存渠道(名称/baseUrl/密钥/模型档位);密钥只存服务端,前端只见掩码。
- `bindings` 表存「角色 → 渠道绑定」:个人覆盖 > 全站绑定 > 默认回落三级解析,`resolve(role, userId)` 确定实际渠道。
- 提示词走 `prompts` 表(版本化),生产可不停机迭代;`agent_*` 系列角色(解题官/命题官/错因分析师/作文三件套等)均有默认绑定。
- 安全:LLM 端点一律 `privateQuery` + 内存滑动窗口限速(默认 20 次/分钟);渠道 baseUrl 校验 `^https://` 且禁内网段(防 SSRF)。

## 六、前端架构(src/)

- **页面路由**:`src/App.tsx` 注册,`src/pages/*.tsx` 一页一文件(Home / SopPage / LibraryPage / PracticePage / WrongBookPage / InsightPage / EssayPage / EssayDraftPage / GeneratePage / HistoryPage / StatsPage / MePage / SettingsPage / AdminPage / ManualPage / GuidePage / InteractivePage / VocabPage / TicketsPage…)。
- **数据请求**:TanStack Query 封装 tRPC;`hooks/useUser` 管登录态、`useToast` 管提示。
- **设计系统**:`components/ink/`(BrushTitle / PaperCard / InkDivider / Seal)是唯一允许的视觉组件源;古风契约:7 个 CSS 变量、`rounded-[2px]`、无图标库、深色模式 `html[data-theme="dark"]`。
- **解析视图族**:`components/analysis/`(五段式解析 / 结构图 / 差异分析 / RetroCard)。
- **错误不静默**:`lib/errorLog.ts` 全局捕获 error/unhandledrejection,保留最近 5 条随工单归档;保存失败必有提示与重试。

## 七、关键横切设计

| 设计 | 位置 | 一句话说明 |
|------|------|-----------|
| 启动自举 | `api/lib/bootstrap.ts` | 迁移 + 种子 + 僵尸清扫 + session 清理,每次启动自愈 |
| 限流 | `api/lib/rate.ts` | 内存滑动窗口,LLM/写库端点防刷 |
| 错误处理 | `contracts/errors.ts` | 前后端统一错误码 |
| 自动草稿 | `src/pages/PracticePage.tsx` 等 | `ky_draft_*` 30s 节流,交卷清除 |
| 沉浸模式 | `hooks/useShortcuts.tsx` | ⛶ + ←→/1234/Enter/Esc 快捷键 |
| 导出 | `api/exportRouter.ts` | 全量备份/恢复(JSON);MD 模板在 `lib/exportMarkdown.ts` |

## 八、迭代与验收

- 方案先行:每个版本先写 `verifier/PLAN_v*.md` → 实现 → 验收记录 `verifier/runs/`(追加式)。
- 验收标准:`verifier/vN/CRITERIA.md`;完整测试脚本在开发环境 `/mnt/agents/tmp_tests/`,仓库 `verifier/v1/` 保留基线。
- 交付门禁:全量回归 + 干净树部署模拟(构建 → 启动 → 健康检查)。
