# 部署指南

本文档覆盖「纸上功夫」的三种部署方式:本地开发部署、单机生产部署(Docker Compose)、以及从全量数据快照还原数据。全部命令以 Linux/macOS 为准,Windows 请相应替换路径与命令(如 `set NODE_ENV=production`)。

## 环境要求

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| Node.js | ≥ 20 | 与 Dockerfile 的 `node:20-slim` 一致 |
| MySQL | 8.0+ | 也可用 TiDB(兼容 MySQL 协议);**必须 UTC 时区**(`--default-time-zone='+00:00'`),否则任务僵尸判定等 TIMESTAMP 逻辑会偏 8 小时 |
| npm | ≥ 10 | 随 Node 附带 |
| 内存 | ≥ 1GB | 构建阶段较吃内存,建议 2GB 以上 |

需要准备一个可用的 LLM 渠道(OpenAI / DeepSeek / 中转等),用于解题流水线与 AI 功能。

## 一、本地开发部署(最快上手)

```bash
# 1. 安装依赖
npm ci

# 2. 准备环境变量
cp .env.example .env

# 3. 填写 .env(至少两项)
#    DATABASE_URL=mysql://用户名:密码@127.0.0.1:3306/kaoyan
#    APP_ID=任意字符串(建议随机)
#    APP_SECRET=任意长随机字符串(用于 JWT 签名)

# 4. 创建数据库(如果不存在)
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS kaoyan CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 5. 构建并启动
npm run build
NODE_ENV=production node dist/boot.js
```

首次启动自动完成:建表(幂等迁移)→ 种子数据(SOP 条款/真题语料/预置渠道)→ 创建管理员账号。

管理员账号:
- 设置了 `ADMIN_PASSWORD` 环境变量 → 用它作为初始密码
- 未设置 → 启动日志打印一次随机密码(仅首次可见,之后只存哈希)

访问 `http://127.0.0.1:3000`。

## 二、Docker Compose 部署(推荐生产)

仓库提供了 `docker-compose.yml`(MySQL 8 + 应用一体编排):

```bash
# 1. 复制环境变量(compose 会读取 .env 中的 APP_ID / APP_SECRET / ADMIN_PASSWORD)
cp .env.example .env
# 按需填写,其中 DATABASE_URL 应使用 compose 内的服务名:
# DATABASE_URL=mysql://kaoyan:kaoyan_pass@mysql:3306/kaoyan

# 2. 一键构建并启动
docker compose up -d --build

# 3. 查看日志(首次启动拿管理员随机密码)
docker compose logs -f app
```

- 应用监听 `http://127.0.0.1:3000`(如需对外,改 `docker-compose.yml` 的端口映射,并在反向代理处配 HTTPS)。
- 数据目录:MySQL 数据保存在 named volume `mysql-data`,重建容器不丢数据。
- 升级:拉取新代码后重新 `docker compose up -d --build`,启动时自动跑新迁移(幂等),无需手工迁移。

## 三、从全量数据快照还原(脱敏基线)

仓库随附 `db/dump.tar.gz`(30 张表、2763 行内容数据,渠道 API key 与账号口令已脱敏为 `sk-REDACTED-*`)。用于新环境快速获得完整演示数据,或作为回归基线。

```bash
# 1. 全新空库部署(见上文任一方式,先让自举迁移建表,可起服务后 Ctrl+C)
cp .env.example .env      # 填好 DATABASE_URL(空库)
npm ci && npm run build
NODE_ENV=production node dist/boot.js   # 建表完成后 Ctrl+C

# 2. 解包并导入
tar -xzf db/dump.tar.gz   # 解出 db/dump_parts/ 分片
node scripts_restore_dump.mjs   # 追加模式导入,只对空库执行

# 3. 重新启动服务
NODE_ENV=production node dist/boot.js
```

注意事项:
- 快照为「追加模式」,**只对空库执行**;已有数据的环境请勿直接导入,避免主键冲突。
- 导入后请到「设置 → API 设置」重新配置渠道密钥(`sk-REDACTED-*` 占位不可用)。
- 重新导出当前库快照:`node scripts_export_dump.mjs`(会生成新的 `db/dump.tar.gz`)。

## 四、反向代理与 HTTPS(可选)

单进程只监听 HTTP,建议在 Nginx 前置终止 TLS:

```nginx
server {
    listen 443 ssl;
    server_name your.domain.com;
    ssl_certificate     /path/fullchain.pem;
    ssl_certificate_key /path/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;   # 解题流水线单阶段可能较长,放宽超时
    }
}
```

## 五、常见问题

| 现象 | 原因与解决 |
|------|-----------|
| 启动报 `DATABASE_URL` 缺失 | `.env` 未配置或未加载,确认已 `cp .env.example .env` 并填好连接串 |
| 首次启动日志无随机密码 | 设置了 `ADMIN_PASSWORD`;或服务已在别处初始化过 |
| 连接数据库失败 | 确认 MySQL 已启动、账号有权限、库字符集为 utf8mb4 |
| 僵尸任务迟迟不被识别/任务永不超时 | MySQL 实例时区不是 UTC。drizzle 以 planetscale 模式解析 TIMESTAMP,会话时区若为 +8,读到的值会偏大 8 小时,导致心跳判定失真。启动 mysqld 加 `--default-time-zone='+00:00'`(docker-compose 已内置) |
| 解题/生图调用超时 | LLM 渠道慢或密钥失效;到「设置 → API 设置」检查绑定与渠道状态 |
| 提示「服务重启,任务中断,可点重试续跑」 | 正常现象:任务生命周期设计,重启后旧 running 任务自动置 error,点击重试从断点续跑 |
| 端口 3000 被占用 | 修改 `NODE_ENV=production PORT=3001 node dist/boot.js`(PORT 环境变量) |

## 六、升级流程

1. 备份数据(可选但推荐):`node scripts_export_dump.mjs`。
2. 拉取最新代码,`npm ci && npm run build`(Docker 方式直接 `docker compose up -d --build`)。
3. 启动服务:新迁移自动幂等应用,僵尸任务自动清扫。
4. 跑一遍验收冒烟(如有测试环境),确认核心链路正常。
