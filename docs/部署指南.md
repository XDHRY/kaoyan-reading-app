# 部署指南

本文档覆盖「纸上功夫」的部署方式:云服务器一条命令部署(推荐,APK 公网直连场景)、本地开发部署、Docker Compose 部署、数据快照还原,以及 CORS / 备案 / IP 直连要点。全部命令以 Linux/macOS 为准,Windows 请相应替换路径与命令。

## 环境要求

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| Node.js | ≥ 20 | 与 Dockerfile 的 `node:20-slim` 一致(仅裸机部署需要) |
| MySQL | 8.0+ | 也可用 TiDB(兼容 MySQL 协议);**必须 UTC 时区**(`--default-time-zone='+00:00'`),否则任务僵尸判定等 TIMESTAMP 逻辑会偏 8 小时 |
| Docker | ≥ 24 | 云服务器一键部署会自装 |
| 内存 | ≥ 1GB | 构建阶段较吃内存,建议 2GB 以上 |

需要准备一个可用的 LLM 渠道(OpenAI / DeepSeek / 中转等),用于解题流水线与 AI 功能。

## 〇、云服务器一条命令部署(推荐,APK 公网直连场景)

适用于 Ubuntu/Debian 全新轻量服务器(带公网 IP)。脚本会:装 Docker → 克隆仓库(分支 `main`)→ 交互式生成 `.env`(管理员密码必填,其余可回车取默认)→ `docker compose up -d --build` → 等待健康 → 输出访问信息。

```bash
# 1. 下载脚本并执行(root 运行)
curl -fsSL https://raw.githubusercontent.com/XDHRY/kaoyan-reading-app/main/deploy/cloud-init.sh -o cloud-init.sh
sudo bash cloud-init.sh
```

脚本幂等:重复执行会跳过已装 Docker、更新代码、保留已有 `.env`(询问确认)。如需自定义代码目录:`APP_DIR=/data/kaoyan sudo bash cloud-init.sh`。

完成后:

- 访问:`http://<服务器公网IP>:<APP_PORT>`(默认 3000;轻量服务器公网 IP 在控制台查看)。
- 管理员:账号 `admin`,密码即部署时填写的 `ADMIN_PASSWORD`。
- 数据恢复(仅空库,可选):

```bash
cd /opt/kaoyan-reading-app
tar -xzf db/dump.tar.gz                      # 解出 db/dump_parts/ 分片
docker compose --profile restore run --rm restore   # 追加导入后容器退出
```

- 防火墙:若开启 ufw,放行 `ufw allow <APP_PORT>/tcp`。

### 备案 / IP 直连要点

- **免备案直连**:国内云服务器用「**IP + 非 80/443 端口**」(如 `http://1.2.3.4:8080`)直连**无需 ICP 备案**,轻量服务器开箱即用——这也是 `APP_PORT` 参数化的原因。
- **80/443 端口**:未备案域名的 80/443 端口常被运营商拦截;若要用 `http://<IP>:80` 或域名访问,须先完成 ICP 备案,并建议 Nginx 反代 + HTTPS(见第四节)。
- **安全提示**:公网直连务必设置 `ADMIN_PASSWORD` 并修改数据库口令;数据库端口(`DB_PORT`)不建议对公网开放,必要时只放行应用端口。

## 一、本地开发部署(最快上手)

```bash
# 1. 安装依赖
npm ci

# 2. 准备环境变量
cp .env.example .env

# 3. 填写 .env(至少两项)
#    DATABASE_URL=mysql://用户名:密码@127.0.0.1:3306/kaoyan_reading
#    APP_ID=任意字符串(建议随机)
#    APP_SECRET=任意长随机字符串(用于 JWT 签名)
#    ADMIN_PASSWORD=管理员初始密码(可选,未设则启动时打印一次随机密码)

# 4. 创建数据库(如果不存在)
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS kaoyan_reading CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 5. 构建并启动
npm run build
NODE_ENV=production node dist/boot.js
```

首次启动自动完成:建表(幂等迁移)→ 种子数据(SOP 条款/真题语料/预置渠道)→ 创建管理员账号。

管理员账号:
- 设置了 `ADMIN_PASSWORD` 环境变量 → 用它作为初始密码
- 未设置 → 启动日志打印一次随机密码(仅首次可见,之后只存哈希)

访问 `http://127.0.0.1:3000`。

## 二、Docker Compose 部署

仓库提供 `docker-compose.yml`(MySQL 8 + 应用一体编排),口令与端口全部从 `.env` 读取并带默认值,且带健康检查:

```bash
# 1. 复制环境变量并填写(必填 ADMIN_PASSWORD)
cp .env.example .env

# 2. 一键构建并启动(--wait 可等到健康后才返回)
docker compose up -d --build
docker compose up -d --build --wait
```

`.env` 关键变量(完整见 `.env.example`):

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `ADMIN_PASSWORD` | 空(随机生成) | 管理员初始密码,**生产必填** |
| `DATABASE_URL` | `mysql://kaoyan:kaoyan_pass_change_me@mysql:3306/kaoyan_reading` | 应用连库串;改了口令必须同步 |
| `MYSQL_DATABASE` | `kaoyan_reading` | 库名(与 `DATABASE_URL` 一致) |
| `MYSQL_PASSWORD` | `kaoyan_pass_change_me` | 业务账号口令,生产请修改 |
| `APP_PORT` | `3000` | 应用宿主机端口(免备案建议 8080) |
| `DB_PORT` | `3306` | MySQL 宿主机端口(本机已有 MySQL 请改 3307) |
| `CORS_ORIGINS` | 空 | 额外 CORS 白名单,APK 场景无需配置(见第五节) |

- 应用监听容器内 `3000`,映射到宿主机 `${APP_PORT:-3000}`。
- app 服务健康检查:`node -e fetch('http://127.0.0.1:3000/api/trpc/ping')`,`start_period` 60s 覆盖「迁移 + 种子 + 管理员创建」异步自举窗口(`boot.ts` 先起监听再自举,健康检查不能只看端口)。
- 数据目录:MySQL 数据保存在 named volume `mysql-data`,重建容器不丢数据。
- 升级:拉取新代码后重新 `docker compose up -d --build`,启动时自动跑新迁移(幂等),无需手工迁移。

## 三、从全量数据快照还原(脱敏基线)

仓库随附 `db/dump.tar.gz`(30 张表、2763 行内容数据,渠道 API key 与账号口令已脱敏为 `sk-REDACTED-*`),解压产物为 `db/dump_parts/`(已 gitignore)。用于新环境快速获得完整演示数据,或作为回归基线。

**容器内一键还原(Docker 部署,推荐)**——先按上文部署起服务(自举建表),再:

```bash
cd 项目目录
tar -xzf db/dump.tar.gz   # 解出 db/dump_parts/ 分片
docker compose --profile restore run --rm restore
```

`restore` 是一次性服务(profile 隔离,默认 `up` 不启动):等待 MySQL 健康后挂载宿主机 `db/dump_parts/` 执行 `scripts_restore_dump.mjs`(追加模式),导入完成即退出。

**裸机还原**:

```bash
# 1. 全新空库部署(见上文任一方式,先让自举迁移建表,可起服务后 Ctrl+C)
# 2. 解包并导入
tar -xzf db/dump.tar.gz
node scripts_restore_dump.mjs   # 追加模式导入,只对空库执行
# 3. 重新启动服务
NODE_ENV=production node dist/boot.js
```

注意事项:
- 快照为「追加模式」,**只对空库执行**;已有数据的环境请勿直接导入,避免主键冲突。
- 导入后请到「设置 → API 设置」重新配置渠道密钥(`sk-REDACTED-*` 占位不可用)。
- 重新导出当前库快照:`node scripts_export_dump.mjs`(会生成新的 `db/dump.tar.gz`)。

## 四、反向代理与 HTTPS(可选)

单进程只监听 HTTP,建议在 Nginx 前置终止 TLS:

```nginx
server {
    listen 443 ssl;
    server_name your.domain.com;
    ssl_certificate     /path/fullchain.pem;
    ssl_certificate_key /path/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;   # 解题流水线单阶段可能较长,放宽超时
    }
}
```

## 五、CORS 与移动端(APK)访问

后端 CORS 白名单见 `api/boot.ts` 的 `isAllowedOrigin`,默认放行:

- **同源请求**(Web/EXE 走相对路径,无 Origin 或同源)不受影响;
- **APK 壳**:WebView 的 origin 固定为 `capacitor://localhost`,已在默认白名单——**公网 IP 直连无需任何 CORS 配置**;
- `localhost` / `127.0.0.1` 与局域网私有段(`192.168.*` / `10.*`,仅 http)。

仅当存在**独立域名/独立端口的前端站点**跨域访问时才需要显式配置(逗号分隔完整 origin):

```bash
# .env 中
CORS_ORIGINS=https://app.example.com,https://admin.example.com
```

修改后重启生效:`docker compose up -d --build`。

## 六、常见问题

| 现象 | 原因与解决 |
|------|-----------|
| 启动报 `DATABASE_URL` 缺失 | `.env` 未配置或未加载,确认已 `cp .env.example .env` 并填好连接串 |
| 首次启动日志无随机密码 | 设置了 `ADMIN_PASSWORD`;或服务已在别处初始化过 |
| 连接数据库失败 | 确认 MySQL 已启动、账号有权限、库字符集为 utf8mb4、`DATABASE_URL` 中的库名/口令与 `MYSQL_*` 一致 |
| 端口被占用 | `APP_PORT` / `DB_PORT` 参数化,改 `.env` 后重启即可;本机裸机运行用 `PORT=3001` |
| 僵尸任务迟迟不被识别/任务永不超时 | MySQL 实例时区不是 UTC。drizzle 以 planetscale 模式解析 TIMESTAMP,会话时区若为 +8,读到的值会偏大 8 小时,导致心跳判定失真。启动 mysqld 加 `--default-time-zone='+00:00'`(docker-compose 已内置) |
| 解题/生图调用超时 | LLM 渠道慢或密钥失效;到「设置 → API 设置」检查绑定与渠道状态 |
| 提示「服务重启,任务中断,可点重试续跑」 | 正常现象:任务生命周期设计,重启后旧 running 任务自动置 error,点击重试从断点续跑 |
| 容器健康检查未通过 | `docker compose ps` 看状态;`docker compose logs app` 看自举日志;`start_period` 已给 60s,若仍超时多为镜像构建/内存不足 |

## 七、升级流程

1. 备份数据(可选但推荐):`node scripts_export_dump.mjs`。
2. 云服务器:重跑 `sudo bash cloud-init.sh`(自动更新代码并 `up -d --build`);裸机:`git pull && npm ci && npm run build`;Docker 方式直接 `docker compose up -d --build`。
3. 启动服务:新迁移自动幂等应用,僵尸任务自动清扫。
4. 跑一遍验收冒烟(如有测试环境),确认核心链路正常。
