# 测试指南（纸上功夫 · verifier 体系）

本文档面向**开发者与维护者**：说明仓库内验收测试的组织方式、每个套件覆盖什么、怎么跑、怎么加断言、以及踩过的坑（限流/时区等）。历史执行记录在 `verifier/runs/`（追加式，不覆盖）。

## 一、目录结构

```
verifier/
├── README.md                 # 索引（append-only）
├── PLAN_v*.md                # 各版本方案（先方案、后实现、再验收）
├── v1/                       # 基线套件（本仓库唯一保留脚本的目录）
│   ├── trpc_call.py          # 底座：tRPC HTTP 调用器（全部套件依赖它）
│   ├── test_v5_api.py        # A/B/C/D 四套件：核心 API 回归（76 项）
│   ├── test_boundary_v6.py   # 边界冲刺：9 大域 137 项（v5.11 新增）
│   ├── verify_extra.py       # 补充验收 40 项（渠道/导出/工单/生词/管理台…）
│   ├── roleplay_v5.py        # 三角色（萌新/老手/管理员）功能遍历 32 项
│   ├── quality_review.py     # 92 条质量量规回归（产物写 E:\temp\quality_exam_1.json）
│   ├── test_pipeline_v5.py   # 六阶段流水线端到端（真实 LLM）

└── runs/                     # 每次执行的带时间戳记录（如 20260808_v511.md）
```

## 二、运行前置条件

| 依赖 | 要求 |
|------|------|
| 服务 | 3000 端口生产服务在跑（`NODE_ENV=production node dist/boot.js`） |
| 数据库 | MySQL 8+ 且**实例 UTC 时区**、连接串带 `timezone:"Z"`（见 `docs/部署指南.md`） |
| 环境变量 | `BASE`（服务地址，默认 `http://127.0.0.1:3000`）、`ADMIN_PASSWORD`（管理密码，默认 `CHANGE_ME_ADMIN_PASS`）、`VERIFY_PASSWORD`（测试账号口令，默认 `CHANGE_ME_USER_PASS`） |
| LLM 渠道 | 仅 LLM 依赖用例需要（B9-B11 / C 组 / pipeline / quality）：先在「设置 → API 设置」配置真实渠道密钥 |
| Python | 3.9+，无需第三方包（仅用标准库） |

|----|------|---------|

| E 降级/空列表 | 新用户全空列表、不存在资源、未绑定角色 resolve | 优雅返回而非 500 |
| F 异常输入 | 方法错用 405、超大 payload、非法 JSON | 统一报错形态 |
| G XSS/注入 | `<script>/onerror/引号分号` 原样存储、SQL 注入尝试不破坏数据 | 存储转义正确 |
| H 合法边界通过 | 恰在 min/max 上的合法输入应成功 | 防止「过严误杀」 |
| I 数据隔离 | 用户 B 无法读/改用户 A 的 essay/ticket/vocab/wrong/personal 渠道 | 防 IDOR |

## 五、已知注意事项（踩坑记录）

### 5.1 限流窗口（重要）

`api/lib/rate.ts` 是**进程内**滑动窗口（默认 60 秒，按 `userId:bucket` 计数）。套件里固定测试账号（如 `v5limit`/`v5newbie`）会反复请求同一端点，**可能撞上限流 429**（表现：同一套件前两次 75/76、某用例偶发失败）。处理：

- **重启服务**即清空内存计数（最简单可靠）；
- 或等待窗口滑过（≤60s）再重跑该用例。

### 5.2 时区口径

数据库实例必须 UTC 启动（`--default-time-zone='+00:00'`），连接串 `timezone:"Z"`。否则 TIMESTAMP 偏大 8 小时，僵尸任务心跳判定失效。详见 `docs/部署指南.md` 与 `verifier/runs/20260808_v510.md`。

### 5.3 数据污染

测试会创建测试账号/渠道/工单，套件自带清理；若数据库被「公告榜」等公共数据污染，清理方式见历史记录。**不要在正式数据库上跑套件**——用独立测试库。

### 5.4 LLM 依赖用例

B9-B11、C 组（出题/洞察/作文）、pipeline、quality 需真实渠道密钥且**消耗额度**；`test_boundary_v6.py` 刻意不触发真实 LLM（LLM 端点只测校验层拒绝），可随时全量跑。

## 六、怎么新增断言

以 `test_boundary_v6.py` 的风格为准（P / expect_err 两个助手）：

```python
# 布尔断言：条件为真即通过，失败打印 extra 辅助定位
P("B1 register name 33 字→400", cond, extra)

# 报错断言：fn 必须抛 TrpcError
expect_err("B2 空密码→400", lambda: anon.mutation("auth.register", {...}), http=400)
expect_err("B3 重名→业务拒绝", lambda: anon.mutation("auth.register", {...}), code="已存在")
```

约定：

- 断言名 = `域字母 + 序号 + 中文描述（输入→预期）`，如 `B24 channel.addModel model 空→400`；
- 同一域一批断言放在一个 `print("══ X. … ══")` 段落里，失败即定位到具体断言名；
- 新增端点先加入 `PRIVATE_ENDPOINTS` / `ADMIN_ENDPOINTS` 矩阵（如果它是私有/管理端点）；
- 数据清理与创建一律通过 API 完成（必要时可用 `dbq()` 直查 MySQL 校验落库，见 test_boundary_v6.py 头部）。

## 七、验收惯例

1. 每次交付：**全量回归 + 干净树部署模拟**（构建 → 启动 → 健康检查）才算完成；
2. `verifier/runs/` 追加带时间戳的记录（如 `20260808_v511.md`），**不覆盖旧记录**；
3. CHANGELOG 每个版本条目都要引用对应验收记录；
4. 版本号规则：每个功能版本必须全量回归通过才能升 `v5.x`。
